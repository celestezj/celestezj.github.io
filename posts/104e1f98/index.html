纯本地实时语音对话系统：ASR + LLM + TTS 全流程落地
最近更新：2026-08-29   |   字数总计：1.3k   |   阅读估时：5分钟   |   阅读量：次

本文由 AI Agent 依据开发手记草稿使用 write-blog skill 自动生成

最近一周下班后，用 ClaudeCode CLI + DeepSeek-v4-flash 全程 vibe coding 搓了一个实时语音对话系统：麦克风进、AI 语音回复出，ASR + LLM + TTS 全流程跑在本地，零云服务。代码拆成三个独立子项目，各带可插拔后端：

  • voice0（TTS）：实现 melo + CosyVoice2（支持零样本音色克隆）。CosyVoice2 是自回归 LLM 式 TTS，本机（RTX 2070 SUPER 8GB）RTF≥1（合成慢于实时），无法流式实时输出；melo 是非自回归模型，一句一次前向推理、速度快，是主力
  • voice1（ASR + 对话编排）：实现 paraformer、whisper 等多种后端引擎。其中流式 paraformer 以非自回归并行解码 + 流式增量识别，兼顾了低延迟与最佳识别准确率，是语音对话的主力
  • llmx（本地 LLM）：llama.cpp + GGUF，支持 Qwen2.5 / Qwen3，8GB 显卡轻松可跑 Qwen3-4B。对话系统对 LLM 能力要求不高，本地部署既免费又完全离线

系统入口在 voice1 项目的 voice_dialogue.py。三种模型、两种接入方式：

  • LLM = 进程外服务化调用：OpenAI 兼容 HTTP（/v1/chat/completions + SSE 流式），LLM 跑在独立进程（本地 llmx 服务或云端 DeepSeek），voice1 只发 HTTP 请求。可先接在线 DeepSeek API 测试，再切本地 llmx，只需改 dialogue/config.local.json 三行配置即可，详见使用文档
  • ASR / TTS = 进程内嵌入：模型以 Python 库形式直接加载进 语音对话进程（python examples/voice_dialogue.py），由后端抽象层（Backend ABC + 注册表）统一调度，与编排代码同进程协作、共享显存

对话系统支持自定义唤醒词唤醒，可通过关键词休眠，或 idletime 超时无对话活动自行休眠，支持指定用户系统提示词，最关键的体验设计是实时可打断：

  • 单进程全链路非阻塞：主线程只采麦克风，ASR / LLM / TTS 各在独立线程并行推进
  • LLM 流式输出按句切分（。！？），逐句入队交给 TTS 串行合成，边说边出、句间无缝
  • AI 播放时半双工门控，说「停下」立即掐断（LLM 流式断连即停 + TTS 队列抢占），人机对话不排队

三个项目同级别目录下放置，可各自独立安装跑通，若使用本地 llm 服务，需要在 llmx 项目目录下先执行run_server.bat --model qwen3-4b，之后在 voice1 项目目录下即可一键启动聊天对话系统：
